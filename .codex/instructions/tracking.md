# Tracking

One job: control issue creation and updates.

## Linear scope

- Identify the repository before any Linear change.
- Read the repository's applicable `AGENTS.md` before that change.
- Create or update a Linear issue only when those instructions permit or require it.
- Do not change Linear when no repository is in scope.
- Do not treat a global skill or generic RFC workflow as authorization.

## Shared issues

- Propose a tracking issue when one fault affects several code areas or branches.
- Keep the proposed issue scope as small as possible.
- If the team fixes the fault, propose that the issue records the selected fix.
